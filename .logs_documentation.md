# WebSocket & Authentication Logging Documentation

## Overview
Comprehensive logging has been added to track WebSocket connections and authentication flows throughout the application.

## Logging Configuration

### Location: `run_server.py`
- **Log Level**: INFO
- **Format**: `%(asctime)s - %(name)s - %(levelname)s - %(message)s`
- **Date Format**: `%Y-%m-%d %H:%M:%S`

### Module-Specific Logging
- `app.api.websocket_routes`: INFO level
- `app.api.auth_routes`: INFO level
- `uvicorn.access`: WARNING level (reduced noise)

## WebSocket Connection Logging

### File: `app/api/websocket_routes.py`

#### Connection Lifecycle
1. **🔌 Connection Attempt**
   ```
   🔌 WebSocket connection attempt from {client_host}:{client_port}
   ```
   - Logged when a client initiates a WebSocket connection

2. **✅ Connection Established**
   ```
   ✅ WebSocket connection established for {client_host}:{client_port}
   ```
   - Logged after successful WebSocket handshake

3. **🔌 Disconnection**
   ```
   🔌 WebSocket disconnected: {client_host}:{client_port}
   ```
   - Logged when client disconnects

#### Authentication Flow
4. **❌ Missing Token**
   ```
   ❌ Auth failed: No token provided from {client_host}:{client_port}
   ```
   - Logged when no authentication token is provided

5. **🔐 Token Verification**
   ```
   🔐 Verifying Auth0 token for {client_host}:{client_port}
   ```
   - Logged when starting token verification

6. **✅ Token Verified**
   ```
   ✅ Token verified successfully for user: {auth0_id}
   ```
   - Logged when token is successfully verified

7. **❌ Token Verification Failed**
   ```
   ❌ Token verification failed from {client_host}:{client_port}: {error}
   ```
   - Logged when token verification fails

#### User Lookup
8. **🔍 Database Lookup**
   ```
   🔍 Looking up user in database: {auth0_id}
   ```
   - Logged when querying database for user

9. **❌ User Not Found**
   ```
   ❌ User not found in database: {auth0_id} from {client_host}:{client_port}
   ```
   - Logged when user doesn't exist in database

10. **✅ User Authenticated**
    ```
    ✅ User authenticated successfully: {email} (ID: {user_id})
    ```
    - Logged when user is successfully authenticated

#### User Settings
11. **📋 Settings Loaded**
    ```
    📋 Loaded user settings for user_id: {user_id}
    ```
    - Logged when custom user settings are found

12. **📋 Default Settings**
    ```
    📋 No custom settings found for user_id: {user_id}, using defaults
    ```
    - Logged when using default settings

## Log Emoji Legend

## Testing the Logs

To see the logs in action:
1. Restart your server: `python run_server.py`
2. Connect a WebSocket client with authentication
3. Watch the console for detailed logging output

## Production Considerations

For production environments, consider:
- Using structured logging (JSON format)
- Implementing log rotation
- Sending logs to a centralized logging service (e.g., CloudWatch, Datadog)
- Adjusting log levels based on environment (DEBUG for dev, INFO/WARNING for prod)
- Masking sensitive information (tokens, passwords)
